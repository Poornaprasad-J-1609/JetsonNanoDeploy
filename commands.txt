GRALLATOR_DEPLOY command guide
==============================

Run all commands from this folder:

cd /path/to/GRALLATOR_DEPLOY

For a migrated system, change these device variables after checking which
/dev/ttyUSB* belongs to each device:

export CAN0=/dev/ttyUSB0
export FRONT_CAN=/dev/ttyUSB0
export BACK_CAN=/dev/ttyUSB1
export FR_CAN=/dev/ttyUSB0
export FL_CAN=/dev/ttyUSB1
export BR_CAN=/dev/ttyUSB2
export BL_CAN=/dev/ttyUSB3
export IMU_PORT=/dev/ttyUSB2
export PYTHONPATH="$PWD/src"

For 4-CAN plus real IMU, use a fifth serial device for IMU, for example
export IMU_PORT=/dev/ttyUSB4. The controller will stop at startup if the IMU
port matches any CAN port.

CAN topology options:

1 CAN, all 12 motors on one adapter:
  --can-count 1 --can-ports "$CAN0"

2 CAN, front legs on one adapter and back legs on one adapter:
  --can-count 2 --can-ports "$FRONT_CAN" "$BACK_CAN"

4 CAN, one adapter per leg. The port order is FR FL BR BL:
  --can-count 4 --can-ports "$FR_CAN" "$FL_CAN" "$BR_CAN" "$BL_CAN"

The examples below use the 2-CAN front/back topology. Replace only the
--can-count/--can-ports lines when your wiring is 1-CAN or 4-CAN.

If the GUI does not open from a desktop terminal, check:

echo $DISPLAY
export DISPLAY=:0

Install Python requirements:

/usr/bin/python3 -m pip install -r requirements.txt

Ubuntu/Debian GUI dependency if tkinter is missing:

sudo apt-get update
sudo apt-get install -y python3-tk

2. Joystick connection test
---------------------------

/usr/bin/python3 src/joystick_interface.py \
  --source joystick \
  --list-joysticks \
  --joystick-wait-seconds 10

To see raw axes/buttons:

/usr/bin/python3 src/joystick_interface.py \
  --source joystick \
  --joystick-wait-seconds 10 \
  --seconds 30 \
  --hz 20 \
  --show-raw

Main controller workflow:

1. Start with the robot manually in crouch/default pose.
2. Normal controller startup is passive: no software-zero and no MIT hold
   command stream is sent when the program opens.
3. Keyboard controls: space = stand, c = crouch/default, h = hold current
   position, up/down arrows = speed up/down, x = emergency stop.
4. Press h only when you want to hold the current pose. Press space or c to
   start a pose transition. The first space/stand command can software-zero the
   current crouch/default frame if needed; c/crouch commands q=0 and never
   redefines the current pose as zero.

6. Motor encoder check only, no hardware zero
---------------------------------------------

This only polls encoder feedback and shows safe joint radians. It disables the
hardware set-zero key so pressing s cannot write zero to the RobStride motors.

/usr/bin/python3 src/check_motor_connections.py \
  --can-count 2 \
  --can-ports "$FRONT_CAN" "$BACK_CAN" \
  --all \
  --rate 20 \
  --print-every 1.0 \
  --disable-set-zero-key \
  --disable-crouch-key \
  --gui-only
  

Keyboard while this command is running:

q = quit

9. Keyboard sit/stand only, fake IMU
------------------------------------

This sends real MIT commands. Keep the robot suspended/secured.
Walking is disabled by the huge walk threshold and zero velocity limits.
Keys after launch: space = stand, c = crouch/default, h = hold current
position, x = emergency stop. Startup is idle: no auto-zero and no auto-hold.

/usr/bin/python3 src/main_controller.py \
  --mode mit-signal \
  --can-count 2 \
  --can-ports "$FRONT_CAN" "$BACK_CAN" \
  --feedback-source mit \
  --command-source keyboard \
  --imu-source fake \
  --no-imu-stabilization \
  --no-gait-assist \
  --base-lin-vel-source zero \
  --start-control-mode idle \
  --startup-action hold \
  --initial-zero-frame crouch \
  --no-auto-zero-on-startup \
  --auto-stand-zero \
  --auto-sit-zero \
  --crouch-calibration-value 0.0 \
  --stand-calibration-value 0.0 \
  --policy-steps 0 \
  --walk-command-threshold 999 \
  --max-vx 0.0 \
  --max-vy 0.0 \
  --max-yaw 0.0 \
  --speed-scale-initial 0.05 \
  --speed-scale-min 0.05 \
  --speed-scale-max 0.05 \

  --gui

------------------------------------------------------

and stand auto-zero completes, the RL policy keeps running with zero velocity
command. The policy receives live projected_gravity, gyro, encoder positions,
encoder velocities, and previous_action exactly like walking mode. Use this to

12. Simulation-match policy input switches
------------------------------------------

Use these only after the safe preview is behaving correctly. They make policy
inference closer to play_grallator_keyboard.py by removing deploy-only command
caps, action clipping, and action smoothing. Keep the robot suspended/secured.

Replace these switches in section 10 or 11:

  --speed-scale-initial 1.0 \
  --speed-scale-min 1.0 \
  --speed-scale-max 1.0 \
  --policy-command-gain 1.0 \
  --policy-command-vx-max 0.0 \
  --policy-command-vy-max 0.0 \
  --policy-command-yaw-max 0.0 \
  --policy-action-clip 0.0 \
  --policy-action-smoothing 0.0 \

Keyboard W/S alone sends only +/-1.8 vx to the policy. A/D alone sends only
/-0.8 vy. Combined W+A/W+D/S+A/S+D sends xy diagonal commands, matching the
IsaacSim keyboard script. Yaw is still disabled in keyboard deploy commands
because the current terminal control request uses only W/A/S/D.
