GRALLATOR_DEPLOY command guide
==============================

Run all commands from this folder:

cd /path/to/GRALLATOR_DEPLOY

For the official SocketCAN path, use Linux CAN channel names. The examples
below work with slcan0/can0 style channels and select SocketCAN automatically:

export CAN0=slcan0
export FRONT_CAN=can0
export BACK_CAN=can1
export FR_CAN=can0
export FL_CAN=can1
export BR_CAN=can2
export BL_CAN=can3
export IMU_PORT=/dev/ttyUSB0
export PYTHONPATH="$PWD/src"

# Keep enough room for one 12-motor set without allowing hundreds of stale
# position targets to queue behind a temporarily busy slcan adapter.
sudo ip link set "$CAN0" txqueuelen 32

All policy, feedback, enable, stop, and motor-check traffic now uses the same
29-bit extended-ID SocketCAN framing as src/robstride_official_zero.py. Use
--can-backend socketcan explicitly when desired. The old /dev/ttyUSB AT packet
transport remains available only with --can-backend serial-at.

Motor rotation signs are configured only in config/motor_directions.yaml.
+1 follows the motor's positive encoder direction (clockwise from the chosen
motor viewpoint); -1 reverses it. The same sign is applied to command and
feedback coordinates. Restart the controller after editing this file.

CAN topology options:

1 CAN, all 12 motors on one adapter:
  --can-count 1 --can-ports "$CAN0" --can-backend socketcan --can-bitrate 1000000

2 CAN, front legs on one adapter and back legs on one adapter:
  --can-count 2 --can-ports "$FRONT_CAN" "$BACK_CAN" --can-backend socketcan --can-bitrate 1000000

4 CAN, one adapter per leg. The port order is FR FL BR BL:
  --can-count 4 --can-ports "$FR_CAN" "$FL_CAN" "$BR_CAN" "$BL_CAN" --can-backend socketcan --can-bitrate 1000000

The examples below use the 2-CAN front/back topology. Replace only the
--can-count/--can-ports lines when your wiring is 1-CAN or 4-CAN.

If the GUI does not open from a desktop terminal, check:

echo $DISPLAY
export DISPLAY=:0

Install Python requirements:

/usr/bin/python3 -m pip install -r requirements.txt

Verify the approved policy artifact and fixed 48-observation contract:

/usr/bin/python3 src/check_policy_contract.py

Replay and compare IsaacLab policy/motor CSV logs against deployment:

/usr/bin/python3 src/compare_sim_policy_logs.py \
  grallator_sim_policy_input_log_20260701_065137.csv \
  grallator_sim_motor_log_20260701_065137.csv \
  --output logs/sim_replay_comparison_20260701_065137.csv

Every main_controller CSV includes the complete policy data path in verified
policy joint order: obs_000..047 (input), action_00..11 (raw policy output),
sent_action_00..11 (output after optional filtering), q_target_00..11 (MIT
position target), qd_target_00..11 (MIT joint-velocity target), and
q_00..11/qd_00..11 (joint-radian feedback). Command, IMU status, torque
summaries, policy SHA256, and policy_joint_order are also saved. Use
--log-every 1 when every 50 Hz control step must be recorded.

Each main_controller run automatically commits and pushes only its completed
CSV after motor stop frames are sent and CAN is closed. Use
--no-auto-push-log for an offline run. The Jetson must have Git SSH
authentication configured. The publisher refuses to push if the branch
contains any unpushed non-log commit, so source changes cannot be uploaded
accidentally.

The controller prints the selected policy SHA256 at startup. It refuses an
unrecognized policy unless --allow-policy-hash-mismatch is passed explicitly
after the replacement artifact has been independently verified.

Ubuntu/Debian GUI dependency if tkinter is missing:

sudo apt-get update
sudo apt-get install -y python3-tk

14. Official RobStride SocketCAN hardware-zero verification
-----------------------------------------------------------

This path requires SocketCAN interfaces such as slcan0 or can0/can1. Install
the official SDK dependencies, bring the channels up, and verify them:

/usr/bin/python3 -m pip install -r requirements.txt

sudo ip link set can0 down 2>/dev/null || true
sudo ip link set can0 type can bitrate 1000000
sudo ip link set can0 up

sudo ip link set can1 down 2>/dev/null || true
sudo ip link set can1 type can bitrate 1000000
sudo ip link set can1 up

ip -details link show can0
ip -details link show can1

Place every motor at the intended physical zero pose. Run the official raw
reader and enter s only after all 12 MECHANICAL_POSITION reads are connected:

/usr/bin/python3 src/robstride_official_zero.py \
  --can-count 2 \
  --channels "$FRONT_CAN" "$BACK_CAN" \
  --model rs-04

Power motors off and back on. Do not press s again. Verify persisted raw zero:

/usr/bin/python3 src/robstride_official_zero.py \
  --can-count 2 \
  --channels "$FRONT_CAN" "$BACK_CAN" \
  --model rs-04 \
  --read-only

The utility logs raw official mechanical position, measured position,
mechanical offset, and zero state under logs/robstride_official_zero_*.csv.
It deliberately performs no software-zero, direction conversion, pose snap,
or modulo/2*pi correction.

  --hz 20 \
  --show-raw

Main controller workflow:

1. Set RobStride hardware zero once with the robot physically standing.
2. Normal controller startup is passive: no software-zero and no MIT hold
   command stream is sent when the program opens. Hardware stand zero is fixed.
3. Keyboard controls: space = stand, c = crouch/default, h = hold current
   position, up/down arrows = speed up/down, x = emergency stop.
4. Press h only when you want to hold the current pose. Press space to command
   stand q=0, or c to command config/default_pose.yaml crouch_pose. Walking is
   blocked until stand reaches its target. No pose command changes motor zero.

12. Simulation-match policy input switches
------------------------------------------

Use these only after the safe preview is behaving correctly. They make policy
inference closer to play_grallator_keyboard.py by removing deploy-only command
caps, action clipping, and action smoothing. Keep the robot suspended/secured.

Replace these switches in section 10 or 11:

  --max-vx 0.80 \
  --max-vy 0.80 \
  --max-yaw 0.80 \
  --speed-scale-initial 1.0 \
  --speed-scale-min 1.0 \
  --speed-scale-max 1.0 \
  --policy-command-gain 1.0 \
  --policy-command-vx-max 0.0 \
  --policy-command-vy-max 0.0 \
  --policy-command-yaw-max 0.0 \
  --policy-action-clip 0.0 \
  --policy-action-smoothing 0.0 \
  --log-every 1 \

With the switches above, keyboard W/S sends exactly +/-0.8 vx to the policy.
A/D sends +/-0.8 vy and Q/E sends +/-0.8 yaw. Combined movement keys send
translation/diagonal/yaw commands matching the logged IsaacSim convention.
